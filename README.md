# NDA Redlining (MLE Take-Home)

LLM-powered redlining: read an NDA, audit it against a structured playbook,
and emit clause-level findings with proposed fixes.

Two surfaces share the same logic:

- **CLI** (the spec deliverable) — `redline.py` + `evaluate.py`, pure Python.
- **Web UI** (bonus) — Next.js app under `web/`, same prompt and validation.

---

## Quick start (CLI — the deliverable)

Requires Python 3.8+ and an Anthropic or OpenAI API key.

```bash
# 1. Clone and enter the repo
git clone https://github.com/krahimov/red-lining.git
cd red-lining

# 2. Install
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# 3. Set your key (auto-detects provider from the prefix)
export ANTHROPIC_API_KEY="sk-ant-..."
# or: export OPENAI_API_KEY="sk-..."

# 4. Run
python redline.py        # reads bad_document.txt + playbook.json, writes redline_output.json
python evaluate.py       # compares redline_output.json against expected_output.json, writes evaluation.txt
```

That's it. No Docker, no DB, no extra services.

### CLI flags

Both scripts accept the same overrides:

| Flag | Default | Notes |
| --- | --- | --- |
| `--document <path>` | `bad_document.txt` | Source NDA. Plain text or RTF (auto-stripped). |
| `--playbook <path>` | `playbook.json` | Clause rules. |
| `--output <path>` | `redline_output.json` | Where to write findings. |
| `--provider {anthropic,openai}` | auto from key prefix | Override detection. |
| `--model <id>` | `claude-sonnet-4-6` (Anthropic) / `gpt-4o-2024-08-06` (OpenAI) | Pin a specific model. |
| `--api-key <key>` | `$ANTHROPIC_API_KEY` / `$OPENAI_API_KEY` | Bypass env vars. |

For richer evaluation (semantic fix-quality instead of lexical):

```bash
python evaluate.py --use-llm-judge   # extra API call per matched pair
```

### Expected output

`redline_output.json` is a JSON array, one entry per finding, exactly the spec format:

```json
[
  {
    "text_snippet": "exact verbatim quote from the document",
    "playbook_clause_reference": "exact clause name from the playbook",
    "suggested_fix": "drafted replacement grounded in the playbook's ideal example"
  }
]
```

`evaluation.txt` reports precision / recall / F1, per-clause hits, matched / missed / spurious lists, and a fix-quality score.

## Bonus: Web UI

A Next.js app under `web/` that wraps the same prompt + validation in an editorial interface — drop a document, watch the marginalia render.

Requires Node 20+.

```bash
cd web
npm install
cp .env.local.example .env.local        # paste ANTHROPIC_API_KEY into the file
npm run dev                             # http://localhost:3000
```

Once running:
1. Drop `bad_document.txt` (or the original `.rtf`) on the **document** zone.
2. Optionally drop `playbook.json` on the **playbook** zone (otherwise the bundled 16-clause NDA playbook is used).
3. Wait ~50 seconds. The result page shows the document with crimson redlines and numbered marginal notes pairing each finding to its clause + proposed redraft.

## How it works

### Detection (`redline.py`)

One LLM call. The prompt sends:
- The full document.
- A compacted view of the playbook (clause name, definition, red flags, ideal/fallback example).

It forces JSON output and requires `text_snippet` to be a *verbatim* substring of the document. A post-call validator drops any entries whose snippet doesn't actually appear in the source — this catches a common failure mode where the model paraphrases the quote, and prevents downstream evaluation from rewarding hallucinated text.

### Evaluation (`evaluate.py`)

Greedy match between predicted and expected redlines using:

```
score = 0.5 * (clause names equal) + 0.5 * snippet_similarity
```

`snippet_similarity` averages a SequenceMatcher ratio (order-sensitive) and Jaccard token overlap (order-insensitive). A pair counts as a match if the combined score exceeds `MATCH_THRESHOLD = 0.55`. The report breaks down precision, recall, F1, per-clause hits, and the missed / spurious lists.

For fix quality, the default lexical score under-credits paraphrased fixes. Pass `--use-llm-judge` to swap in an LLM scoring how well the candidate captures the same legal protections as the reference — typically jumps the score from ~0.47 to ~0.87 on this dataset.

## Cost

One detection run uses one LLM call: ~11k input tokens, ~3.4k output. On Claude Sonnet 4.6 that's well under $0.15. The $50 budget absorbs many iterations plus the optional LLM-judge run.

## Troubleshooting

- **`No API key`** → export `ANTHROPIC_API_KEY` (preferred) or `OPENAI_API_KEY`, or pass `--api-key`.
- **`401 invalid x-api-key`** in Python but `200` from `curl`** → you have *both* `ANTHROPIC_API_KEY` and `OPENAI_API_KEY` exported and an old shell pinned the wrong one. The fix is in `select_provider_and_key`: pick provider first, then the matching key.
- **Web UI: `ANTHROPIC_API_KEY is not configured`** → Next.js reads `web/.env.local`, not the root `.env`. Copy: `cp .env web/.env.local`, restart `npm run dev`.
- **Model output truncated / `JSON parse failed`** → bump `max_tokens` (currently 4096 in the CLI, 8192 in the web app).
- **`\'93` / `\'94` showing up in quoted snippets** → the input is RTF. The CLI auto-detects this; for the web app it's stripped server-side.
