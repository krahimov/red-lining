# NDA Redlining (MLE Take-Home)

Two scripts that detect and evaluate clause-level issues in an NDA using an LLM
plus a structured playbook.

## Files

| File | Purpose |
| --- | --- |
| `redline.py` | Detect issues in `bad_document.txt` against `playbook.json` |
| `evaluate.py` | Compare `redline_output.json` to `expected_output.json` |
| `bad_document.txt` | Source NDA (problematic clauses) |
| `playbook.json` | Clause-by-clause review rules |
| `expected_output.json` | Reference redlines |
| `redline_output.json` | Generated by `redline.py` |
| `evaluation.txt` | Generated by `evaluate.py` |

## Setup

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# Default model is Claude Sonnet 4.6 via the Anthropic SDK.
export ANTHROPIC_API_KEY="..."

# OpenAI is also supported (auto-detected from sk-... prefix or via --provider openai).
# export OPENAI_API_KEY="..."
```

## Run

```bash
python redline.py                  # writes redline_output.json
python evaluate.py                 # writes evaluation.txt + prints to stdout

# Optional: LLM-as-judge for fix-quality scoring (extra API spend)
python evaluate.py --use-llm-judge
```

CLI flags (both scripts):
- `--provider {openai,anthropic}` — override auto-detection
- `--model <id>` — pin a specific model
- `--api-key <key>` — bypass env vars

## Design notes

**Detection (`redline.py`).** A single LLM call receives the full document and
a compacted view of the playbook (clause name, definition, red flags, ideal
example, fallback example). The prompt forces JSON output, requires
`text_snippet` to be a *verbatim* substring, and constrains
`playbook_clause_reference` to clause names from the playbook.

A post-call validator drops entries whose snippet doesn't actually appear in
the document (a common hallucination mode where the model paraphrases the
source). This keeps the output trustworthy and prevents downstream evaluation
from rewarding fabricated quotes.

**Evaluation (`evaluate.py`).** Predictions are matched to expected redlines
greedily by a combined score:

```
score = 0.5 * (clause names equal) + 0.5 * snippet_similarity
```

`snippet_similarity` averages a SequenceMatcher ratio (order-sensitive) and
Jaccard token overlap (order-insensitive). A pair is counted as a match if
the combined score exceeds `MATCH_THRESHOLD = 0.55`. We report precision,
recall, F1, a per-clause breakdown, and the matched / missed / spurious lists.

For suggested-fix quality, the default mode uses the same lexical similarity.
`--use-llm-judge` swaps that for an LLM scoring how well the candidate
captures the same legal protections as the reference fix; this is more
expressive but costs additional API spend.

## Cost

Default detection run is one LLM call to **Claude Sonnet 4.6**: ~10-12k input
tokens, ~2-3k output. That's well under $0.15 per run, so the $50 budget
absorbs many iterations plus the optional `--use-llm-judge` evaluation.
